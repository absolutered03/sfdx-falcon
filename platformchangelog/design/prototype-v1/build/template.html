    Pipeline

    release feeds→raw notes→summarizer→human review→published

    Every tracked tool has a release feed. New releases land in the registry within hours, with the raw release note attached. The summarizer turns that note into a short list of typed change lines. An editor reads the summary against the source, fixes or rejects it, and only then does it appear in the feed and on the tool page.

    What you see before review

    Versions, dates, titles and links to the source are shown as soon as a release is detected. Change lists marked example in this prototype were written by hand from the source notes to show the design. They are not reviewed entries.

    Change types

    The vocabulary is Keep a Changelog, with one flag. A line is one of added, changed, deprecated, removed, fixed or security. Any line can also carry breaking: true, which shows as the ! in the first gutter column. A security fix is its own type because readers scan for it; a breaking change is a flag because it can apply to a removal, a rename or a changed default alike.

    Version emphasis

    Minor and major releases get an accent rule and a brighter version number. Patch releases are set quieter. Releases carrying a breaking or security line get a tag in the header, so they stand out even in the feed.

    Neutrality

    The registry is vendor neutral. Comparison notes describe differences in model and operating cost, not winners. Nothing on this site is sponsored.
